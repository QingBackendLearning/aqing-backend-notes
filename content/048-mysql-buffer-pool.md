## 说人话
它缓存的是数据页和索引页，帮数据库少去磁盘取页。相同页面能服务不同查询，不只是存上一条 SQL 的答案。

## 先这样回答
InnoDB Buffer Pool 是主要的页缓存区域。修改后的脏页需要刷回磁盘，回收、预读和刷新也占资源。容量、命中和 I/O 要一起看，不能只凭命中率判断整个查询快慢。

## 把原理拆开
索引页已缓存时，沿树访问可能不需要读取磁盘；但扫描很多页、等待锁或 CPU 计算仍可能让 SQL 慢。

## 继续追问
调大一定更好？——还需给连接、其他缓存和操作系统留下资源。

## 容易说错的地方
> Buffer Pool 与历史查询结果缓存不是同一个机制。

## 动手试一遍
为一条慢 SQL 列出页命中、磁盘读取、锁等待和 CPU 四种可能证据。
