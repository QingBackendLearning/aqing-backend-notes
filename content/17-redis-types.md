## 先这样回答
String 适合简单值和计数；Hash 适合字段集合；List 适合有序序列与两端操作；Set 适合去重和集合运算；Sorted Set 适合按分数排序的数据。选择时要看需要什么操作，以及数据量与访问模式。

## 把原理拆开
- 计数器：String 的原子增量操作。
- 用户的部分资料字段：Hash 的字段访问。
- 去重标签：Set。
- 分数排行榜：Sorted Set。
这些是通用设计示例，不是个人线上案例。复杂消息处理如果需要消费组、确认等能力，应评估 Streams 或专门消息系统，而不是仅凭“List 能入队”就判断足够。

## 继续追问
- 逻辑类型和内部编码是同一个概念吗？——不是，内部表示会随数据大小、版本和配置变化。
- 一个超大 Hash 有什么风险？——可能带来热点、大 key 和操作延迟，需要评估拆分与访问方式。

## 容易说错的地方
> 数据类型的使用场景不是唯一对应关系，先说明需要支持的操作。
