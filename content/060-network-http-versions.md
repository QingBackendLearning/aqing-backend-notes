## 说人话
多条请求共用连接时，一条流是否拖住其他流，要看协议把它们放在哪个传输机制上。

## 先这样回答
HTTP/2 在单 TCP 连接上复用多个流，仍受 TCP 字节流层丢包等待影响。HTTP/3 采用 QUIC，减少不同流在传输层的这类互相阻塞，但拥塞与共享资源等影响仍存在。

## 把原理拆开
一条 HTTP/2 流的数据丢包，底层 TCP 需要按序交付，可能影响同连接其他流。不能据此断言 HTTP/3 在所有网络与负载下都更快。

## 继续追问
请求复用就不需要连接规划了吗？——资源限制和故障传播仍需考虑。

## 容易说错的地方
> 要说明是应用请求层还是传输层的队头阻塞。
