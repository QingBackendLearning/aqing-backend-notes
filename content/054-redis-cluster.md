## 说人话
键先被分到固定编号的槽，再由节点负责一批槽。扩容主要是在调整谁负责哪些槽。

## 先这样回答
Redis Cluster 按哈希槽分布键，客户端要处理节点重定向与槽迁移。多键操作通常要求相关键在同一槽，可用 hash tag 协调，但集中到同一槽也可能形成热点。

## 把原理拆开
用户相关的多个 key 可以用共享 hash tag 放到同槽。这样方便原子多键操作，却不等于所有用户都应该集中到一个标签。

## 继续追问
节点数等于槽数吗？——不是，节点可以各负责很多槽。

## 容易说错的地方
> 分片扩容不自动解决一个超热 key 的负载问题。

## 动手试一遍
给三个用户各设计两个 key 的 hash tag，说明如何同用户同槽、不同用户尽量分散。
