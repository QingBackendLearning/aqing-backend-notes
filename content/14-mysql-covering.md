## 说人话
二级索引先告诉你这条记录的主键。要的列都在索引里就够了；缺一列，通常还要去完整记录里取。

## 先这样回答
InnoDB 的聚簇索引叶子记录包含行数据，二级索引记录包含索引列和主键。查询所需数据不在二级索引里时，通常要通过主键到聚簇索引取行，这常被称为回表；若所需列可由索引提供，则可形成覆盖索引访问。

## 把原理拆开
假设 `users` 的主键是 id，二级索引为 `(name)`：
```sql
SELECT id, name FROM users WHERE name = '阿青';
SELECT id, name, email FROM users WHERE name = '阿青';
```
前者的列可从该二级索引中获取；后者还需要 email。是否采用预期的访问路径，应查看实际执行计划。

## 继续追问
- 为什么不把所有列都放入索引？——索引占空间，维护会增加写入成本，宽索引也影响缓存利用。
- 主键太宽有什么代价？——二级索引也存主键，可能一并变大。

## 容易说错的地方
> 覆盖索引是相对于某条查询而言，不是某个索引永远“覆盖一切”。
