## 说人话
证明“你是谁”还不够，每次取订单都要检查“这份订单是不是你能看的”。换一个 URL 里的编号，不能就看到别人的数据。

## 先这样回答
认证确认身份，授权决定是否可执行具体动作或访问对象。服务端应针对用户、租户、角色和资源关系做授权，不能依赖前端隐藏按钮或难猜 ID。

## 把原理拆开
查询可以把资源所属关系纳入条件，更新和删除同样检查。管理员权限也要明确范围；输入校验、参数化查询、限流和审计分别解决其他问题，不能互相代替。

## 继续追问
订单 ID 使用 UUID 后是否可以省掉授权？导出和批量接口怎样防止跨租户混入？

## 容易说错的地方
> 签名 token 有效只代表身份凭据有效，不代表拥有所有对象的权限。

## 动手试一遍
用用户A请求用户B订单、跨租户批量导出和普通用户删除订单三种案例检查服务端。
